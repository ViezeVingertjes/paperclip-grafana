## [Unreleased]

### Added
- `apply-paperclip-otel.py --native` (and `paperclip-native-env.json`): sets `PAPERCLIP_ACPX_PROVIDER_PACKAGE_ROOT` and
  `_MANIFEST` so native `paperclip_runner` agents pass Paperclip's ACPX installation check in the official image.
- README: *Agents that report properly* (login origins, agent JWT secret, Claude Code telemetry for legacy and native
  agents, native-runner checklist, budgets with subscriptions) and matching troubleshooting rows.

### Fixed
- `install.sh` recreates the `paperclip-net` network when the quadlet unit still reports "active" after the network was
  removed, which made the first container that used it fail with `network not found`.

## [1.0.0] - 2026-10-30

First release: a local Grafana dashboard for Paperclip's OpenTelemetry traces, checked against a real Paperclip instance
running real agent work (legacy `claude_local` runs and native `paperclip_runner` runs).

Paperclip exports traces only, so every number is derived from spans: span metrics (PromQL) for rates, error ratios and
means, and TraceQL metrics for percentiles and anything grouped by a span attribute.

### Added
- `dashboards/paperclip.json`, generated by `tools/gen_dashboard.py`: Health, Overview, Runs, Run preparation, Execution and
  completion, Native runner (startup and first token, turns and tools, providers and environment), Workspace, Controller,
  Budget, API, Chat channels (collapsed) and Telemetry pipeline, with an *Instance* variable and trace links.
- Runs are `task.execution_attempt`, which every adapter emits, so the dashboard works for `claude_local`, `codex_local` and
  `paperclip_runner` agents alike; the *Native runner* rows fill for `paperclip_runner` agents.
- `paperclip-otel/`: a Containerfile that adds Paperclip's OpenTelemetry packages to any Paperclip image at exactly the
  versions that image declares (with a `PROTOCOL` build argument), `peer-packages.py` for host installs, a compose override
  example, the export variables, and `apply-paperclip-otel.py` to merge them into an env file.
- `install.sh` (rootless Podman Quadlet on a shared `paperclip-net` network) with `--build-image`, `--paperclip-env`,
  `--join-network` (for an already installed stack) and `--import-dashboard`; `docker-compose.yml`.
- `tools/validate_dashboard.py` (runs every query, including TraceQL metrics, and looks inside collapsed rows),
  `tools/import_dashboard.py`, `tools/send_sample_telemetry.py` (CI only), unit tests, CI, and `examples/alerting/`.
- Docs: telemetry reference, FAQ, upgrade notes, and a README section for people who already run Paperclip.

### Notes
- Percentiles of runs, turns and startups come from TraceQL metrics because span-metric histograms stop at 16.4 s; the
  health tiles compare means (sum / count, exact at any length) with your own last 7 days.
- Paperclip's last Dockerfile stage is a `cloud` variant that breaks the native runner; build with `--target production`.
  The native runner also needs a Claude credential it accepts (`CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`).
- Paperclip exports no PostgreSQL client spans, so the dashboard has no database panels.
